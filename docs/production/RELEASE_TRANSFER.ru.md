# Доставка APK с продолжением передачи

## Обнаруженный сбой

После выпуска интерфейса0.13.0-alpha.236.1 телефон остался на0.12.0-alpha.214.1. Штатная device-recover сначала доказала отсутствие владельца update.lock и архивировала его, не убивая процесс. Повтор delivery получил манифест, но на скачивании APK сработал120-секундный таймаут. Осталось31 339 968байт старого .part. Старый код при повторе открывал этот файл на перезапись, то есть снова скачивал с начала.

## Изменение существующего маршрута

Переиспользован ранее проверенный resumable-download.mjs, а не создан второй установщик. Release-transfer связывает файл с repository/releaseId/assetId, размером и SHA-256 из GitHub asset metadata. Манифест сначала сам проходит проверку digest, затем его ожидаемый SHA-256 APK сверяется с отдельными метаданными APK. Проверки успешного канонического dev CI, commit/tag, package, версии и установленной постоянной подписи остались в прежних update/install.

```text
scripts\chat.cmd delivery
scripts\chat.cmd delivery --commit EXACT_40_CHARACTER_COMMIT
scripts\chat.cmd device-status
```

Второй вариант ищет выпуск именно заданного commit, а не сравнивает только самый новый выпуск. Запрет отката и конфликтов одной версии сохраняется: более новая установленная APK не заменяется старой ради эксперимента.

Передача использует Range/Content-Range и конечные лимиты:90секунд на запрос, до8запросов и6минут на один артефакт. Возобновляемый файл и его metadata имеют неизменяемую идентичность. На окончании обязательно совпадение полного SHA-256 и размера, затем защищённая публикация локального файла и повторное чтение. Если сервер игнорирует Range, существующий helper начинает только свой промежуточный поток заново. Окончательные файлы с другими байтами не перезаписываются.

Redirect проверяется до следующего запроса: только HTTPS и официальные GitHub/CDN-узлы. Локальный адрес, другой origin, credentials или смена lease останавливают передачу. В логах только короткий статус и число байтов; подписанные URL, токены и телефонные идентификаторы не публикуются.

## Старый частичный файл

Старый .part нельзя назвать проверенным только по имени. Он может быть скопирован в отдельный новый поток только при проверенном release-манифесте и совпадающей полной идентичности APK. Журнал хранит SHA-256 скопированного префикса и явно prefixAuthenticated=false. Исходный .part остаётся неизменным. Итоговый полный SHA-256 обязателен; регрессия с подменённым префиксом доказывает, что повреждённый файл не становится готовой APK. Обрыв после копирования, но до записи metadata, восстанавливается только по точному seed-журналу.

## Постоянный updater

После clean/verified/ship выполнить `deploy-agent`: versioned-бандл включает release-transfer и resumable-download, что проверяет тест транзитивных зависимостей. Сохраняются существующие Limited-права,5-минутный интервал и IgnoreNew. Только общий execution-time-limit задачи расширяется до15минут, чтобы не убить разрешённую ограниченную передачу и следующую установку. Ручная delivery также имеет15-минутный внешний лимит.

До фактического deploy-agent это лишь исходниковое исправление, не обновлённая задача Windows. До реального install/readback это только проверенный файл, не новая версия телефона. Отключение телефона не блокирует dev-выпуск. Живые или неизвестные locks не удаляются; device-recover применяется только к независимо подтверждённому отсутствующему владельцу.

## Проверки

Набор release-transfer.test.mjs проверяет свежую передачу, точное повторное использование, продолжение старого и нового префиксов, повреждённый префикс/манифест, потерю ответа/метаданных, несовпадение final, чужой lease, symlink, запрещённый redirect, Range и границы pinned-release/options. Полный verify дополнительно сохраняет прежние generic-download, install/signature/version и игровые регрессии.

Источники протокола: https://www.rfc-editor.org/rfc/rfc9110.html#name-range-requests и https://docs.github.com/en/rest/releases/assets . Поддержка HTTP range не заменяет проверку полной идентичности файла. Установка, физические касания и домашний ярлык подтверждаются отдельными квитанциями; этой документацией они не объявлены выполненными.
