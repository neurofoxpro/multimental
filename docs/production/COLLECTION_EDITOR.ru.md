# Коллекция и редактор для обычного боя с ИИ

Первый вход через «Коллекция и колоды» или «Играть против ИИ» инициализирует рекомендованный alpha-набор: 30 карт по две копии. Используется прежняя идемпотентная транзакция collection_init. Неизвестная непустая коллекция не заменяется. При обычном запуске приложения без входа в редактор новых выдач нет.

Экран показывает несколько именованных колод, поиск RU/EN по карте/стихии/роли, фильтр стихии, характеристики и направления атаки, принадлежность копий и текущий состав. Плюс/минус меняют только черновик. Сохранение, выбор и удаление используют единый ProfileController и дисковый журнал, а не отдельный файл UI.

Правила: 15 карт, не более двух копий, любые сочетания стихий. Можно сохранить неполный черновик, но выбрать его для матча нельзя. Игра начинается выбранной сохранённой колодой; скрытого возврата к STARTER при неполном выборе нет. ИИ пока использует STARTER. Локальный replay содержит оба исходных состава.

Удаление колоды требует подтверждения и не удаляет карты. Переключение/выход/новая колода при несохранённых изменениях требует подтверждения потери черновика. При ошибке сохранения черновик остаётся на экране, повтор примиряется с прежней pending-операцией; sequence не генерируется заново ради обхода ошибки.

## Проверки

`npm run game -- profile-test editor` выполняет изолированные проверки реального UI Godot. Набор встроен в общий verify и обязательные маркеры. Проверяются каталог/поиск/фильтр, лимиты, создание/сохранение/выбор, обычный матч и точный replay, перезапуск, draft без fallback, отмена удаления, потерянное подтверждение записи, повтор и границы интерфейса при 720×1280, 720×1440, 1280×720.

Обучение отдельно проверяется до первого открытия коллекции и при неполной/невыбранной личной колоде: оно использует STARTER и не меняет личный выбор.

Это headless/UI event-тесты, не физические Android-нажатия. В текущей итерации запись нового collection_device_lab.gd остановлена инструментом; этот модуль не существует и не включён другим путём. На Android используются уже существующие profile/smoke/reinstall suites; они не заменяют субъективную и ручную проверку нового экрана.

## Границы версии

Сетевые LAN/Bluetooth комнаты по-прежнему используют стартовые составы. Это явно не завершение всей META-01. Следующий инкремент согласует пользовательские колоды до первого хода, запрещает их замену при reconnect и сохраняет приватность рук. Магазин, паки, пыль, задания и серверный рейтинг не добавлены этим экраном.

Диагностические режимы не инициализируют личную коллекцию: profile.enabled=false. UI-тесты создают отдельный случайный каталог profile-tests и удаляют только собственные файлы после успешной проверки. Личный профиль и ключ подписи не очищаются.

Первичные API для адаптивного списка и фокуса: https://docs.godotengine.org/en/stable/classes/class_scrollcontainer.html и https://docs.godotengine.org/en/stable/classes/class_optionbutton.html. ensure_control_visible применим после завершения кадра layout; тесты ждут process_frame, а не считают мгновенный размер окончательным.
