# Проверки установленной dev-сборки

Один вход: `npm run game -- device-suite --target phone --suite smoke`.
На станции также работает `scripts/chat.cmd device-suite --target phone --suite smoke`.

## Наборы

- `smoke`: закрытие, запуск, JNI, обучение и реальное нажатие по карте/полю. Заканчивается проверкой возврата в меню. Сеть не требуется.
- `lifecycle`: закрытие, запуск, интерфейс; `ui`: только интерфейс.
- `usb`: обмен через ADB-туннель, не тест Wi-Fi.
- `bluetooth`: физический RFCOMM с компьютером, не проверка двух Android.
- `hardware`: USB, Wi-Fi LAN и физический Bluetooth. Недоступный LAN делает весь этот набор неуспешным, даже если остальные шаги прошли.

Неизвестные/повторные параметры и неправильный target отклоняются до доступа к устройству. Radio-наборы требуют phone. Эмуляторы выбираются только из выделенных A/B; их принадлежность проверяет дочерний адаптер.

## Что подтверждает отчёт

У каждого запуска случайный runId; каждый шаг пишет отдельную квитанцию. Сборщик сверяет runId, target, режим, package, время и результат процесса. Старый файл, совпадение имени без идентичности запуска, отсутствующий ответ, сигнал завершения или ошибка не становятся успехом. Поля дочернего JSON не могут переписать exit code процесса.

До и после всего набора читаются версия, versionCode и SHA-256 фактически установленного base.apk. Они должны совпадать с локальной квитанцией установки и оставаться неизменными. Исходники проверяющих скриптов тоже фиксируются fingerprint до/после. Это связывает результат с конкретными APK и инструментами, а не только с названием версии.

На весь набор удерживается qualification.lock: фоновый установщик не должен обновлять приложение между шагами. Существующая активная блокировка не удаляется. Рабочие отчёты и сырые логи остаются локально в `.gameprod/evidence/suites/RUN_ID/`; снимок последнего запуска сохраняет прежнее имя `suite-phone-SUITE.json`. Квитанции шагов и их SHA-256 включены в отчёт.

Suite не удаляет приложение или его данные и не меняет ключ. Отдельный `device-test --mode reinstall --dir ...` проверяет обновление с прежней подписью, сохранение settings и контрольных файлов. Политика Android `install -r`: https://developer.android.com/tools/adb .

Автоматические нажатия, транспорт и сохранность данных не равны субъективной приёмке игры. Успех Bluetooth Windows↔Android не закрывает задачу двух физических Android; отсутствие Wi-Fi не скрывается за успешным USB.
