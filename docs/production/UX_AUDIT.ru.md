# UX-06: измерения и направление редизайна Multimental

Дата проверки первоисточников: 26.09.2026. Первый baseline: dev d4797322eb196981cb6bf99fb61fd4d41f94d02e. Затем срез безопасно обновлён до099d0f5b61546b97407090c7e6a6e7793f050b75, и магазин PR111 включён в повторный набор. Это исследование и воспроизводимый инструмент, не заявление о завершённой доступности или новом художественном стиле.

## Повтор одной командой

`npm run game -- ux-audit` подготавливает изолированный кэш Godot, открывает меню, редактор, бой и магазин на RU/EN при трёх действительных логических viewport:720×1280,720×1440,1280×720. Набор из24 комбинаций проверяется на полноту и уникальность; требуемый и фактический размеры обязаны совпадать. Читаются геометрия, видимость, шрифт и фокус реальных Control. Отчёт — `.gameprod/evidence/ux-audit.json`, с хешами исходников до/после. Профиль случайный тестовый, личные данные не читаются.

Первая пробная версия измерителя выявила собственную ошибку: изменение размера Window без content_scale_size не гарантировало изменение логического viewport. Она исправлена до принятия результатов; нельзя засчитывать три одинаковые геометрии как три ориентации. Короткий видимый край кнопки в ScrollContainer также не считается её полной зоной нажатия: измеряются обе величины раздельно.

## Подтверждённое наблюдением

При720×1280 минимальная полная сторона видимых интерактивных элементов: меню54, редактор50, бой54 единицы Godot. Минимальные размеры назначенного шрифта:14/16/12 соответственно. Это не высота глифа на физическом дисплее и не dp. В редакторе нижняя строка может быть частично видна из-за прокрутки; это не самостоятельное доказательство дефекта.

При1280×720 есть частично обрезанный НЕпрокручиваемый элемент главного меню. Это воспроизводимый кандидат P0 для адаптивного reflow, а не повод уменьшать шрифт. В18 сценах при входе не назначен фокус Control. Это не доказывает невозможность входа через Tab, но требует явной проверки начального/возвращаемого фокуса перед PC/Web-релизом.

Существующая схема «выбрать карту → повернуть → выбрать клетку», явная кнопка атаки, подтверждение дружественного огня и сохранение draft — полезная основа. Их нужно сохранить, а не заменить обязательным перетаскиванием. Решения D19–D21 не меняются редизайном.

## Бюджеты для следующего инкремента

Android-рекомендация: зона взаимодействия не менее48×48dp[1]. Для web базовый WCAG2.2 AA имеет24×24CSSpx с оговорёнными исключениями; для частых игровых действий выбираем более удобную проектную цель44×44CSSpx[2]. Ни48dp, ни44CSSpx нельзя механически сравнивать с50 единицами Godot. Формула для измеренного Android:target_dp=target_viewport×canvas_scale_px×160/densityDpi. Пока реальные масштаб и плотность не прочитаны, результат — unknown, а не pass. При тестовом предположении720viewport=360dp цель48dp соответствует96единицам, но это лишь расчётный сценарий.

Контраст: проектная цель4.5:1 для обычного текста и3:1 для крупного текста/важных нетекстовых контуров[3]. Проверка должна использовать конечные цвета после наложений, modulate и полупрозрачности; функция contrastRatio сама по себе не сертифицирует экран. Принцип: цвет + форма/иконка + понятный текст; состояния своих/чужих и опасной атаки не кодируются одним оттенком[4].

Читаемость: крупная карточка-инспектор по короткому нажатию, сохранение стоимости/здоровья/атаки в стабильных местах, минимум длинных абзацев на клетках. Масштабирование текста и полная кириллица обязательны для последующей проверки; XAG101 рекомендует настраиваемость и измерение реального текста, а не одного font_size[5]. Клавиатура: видимый focus, предсказуемый Tab, возврат к элементу после диалога; явные focus neighbors и grab_focus предоставляет Godot[6].

## Последовательность UX-07

1. P0: адаптивные меню и safe-area контейнер; никаких недоступных команд при landscape/вырезах. Тест фактического viewport, затем настоящий телефон.
2. P1: централизованные tokens размера/отступов/контраста и измерение dp; исправить малые touch-targets, не перекрывая соседей.
3. P1: инспектор карты и краткая область деталей рядом с полем; цена/атака/HP/направления не перемешиваются с длинными объяснениями.
4. P1: до атаки показывать все цели и ответ выживших; предупреждение о своих сохраняется. Не менять правила или раскрывать скрытую руку.
5. P1: keyboard focus, возврат из popup, доступные названия кнопок; затем отдельное исследование реального TalkBack/Web accessibility, без обещания screen-reader support по одному дереву Control.
6. P2: снижение анимаций, контрастные темы и полировка графики; изображения и декоративный стиль не блокируют первичные исправления.

Для каждой части: отдельный PR и критерии; сначала скриншоты/геометрия/сигнальные тесты, затем реальные касания. Пользовательская оценка интереса, темпа и удобства остаётся отдельной BETA-01. Магазин включён в расширенный набор после fast-forward PR111. Исторические значения выше относятся к начальному baseline; свежий JSON содержит24 комбинации и отдельный sourceDigest. Не смешивать старые измерения с новым интерфейсом.

## Варианты компоновки

Рекомендуется Android-портрет: сверху краткий статус, в центре крупное3×3, снизу рука и стабильная область действия; длинные детали открываются отдельно. Desktop/Web-альбом: поле в центре, справа детали, нижняя рука; главный выбор остаётся щелчками. Не рекомендуется: обязательный drag, плотный веер с закрытыми ценами, плавающая кнопка конца хода поверх карт, длинное обучение перед первым боем. Это проектные рекомендации для сравнения прототипов, не результаты A/B людей.
