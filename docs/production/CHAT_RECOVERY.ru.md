# Multimental: восстановленный контекст и границы

Источник — доступная история этого чата, включая исправления владельца. Это структурированное извлечение, не полный дословный экспорт. Проверка внешнего состояния начата 24.09.2026.

## Главное
Единственный репозиторий: neurofoxpro/multimental. Разрешённый компьютер: VENEL-SENDRIK. Подключённый к нему телефон разрешён для установки проверенных версий. Другие компьютеры и репозитории использовать запрещено. Рабочая ветка восстановления: feature/strict-production-20260924. История существующего bootstrap сохранена.

Ранее обещания автоматизации выдавались за выполненную работу, путались репозитории, рекомендовались непроверенные ссылки, был использован неразрешённый компьютер. Эти действия не являются основанием для дальнейших разрешений. Теперь каждая операция имеет конкретную границу и доказательство результата. Не просим повторно уже предоставленные настройки.

## Принятое владельцем
Название Multimental. Дуэльная ККИ/стратегия: общее поле 3x3, карты-юниты, размещение и бой; цель — занять своими юнитами пять клеток раньше соперника либо истощить его руку и колоду одновременно. Азарт, соревнование, свободное построение колод, коллекция; нет обязательного гринда и интернета.

Пять стихий: огонь, вода, молния, воздух, земля. Любая карта может происходить из любой части мультивселенной. Нет отдельных миров для фракций. Фракции свободно смешиваются. Нет врождённых преимуществ стихий. Важнейшая система взаимодействий отложена владельцем; временные численные правила не выдаются за окончательную концепцию.

Android первый, Web последующий. Портретный телефон, альбомный ПК/Web. Сенсор одним пальцем, курсор, вид сверху. Русский и английский. Современные устройства; 16:9/18:9 — опорные раскладки, не единственные допустимые. Матч примерно 10 минут, затянутый не больше 15. Одно действие за ход. Сворачивание не останавливает таймер; два пропуска приводят к поражению. Считать подряд — рекомендация, а не дословное утверждение владельца.

Своя рука и поле видны, рука соперника и порядок колод скрыты. Добор, первый игрок, содержимое паков случайны. Карты коллекции после поражения сохраняются. Рейтинг без уменьшения заявлен владельцем; точный рейтинг отложен, не подменять скрытым Elo без решения.

Боевые монеты оплачивают карты; ещё два ресурса в будущем. В лобби отдельные деньги для паков и пыль для крафта. Пак — пять карт. Коллекция, сборка колод, задания, уровни. Конкретные цены, дубликаты, гарантии редкости и смысл уровней пока не окончательны. Игрок крафтит экземпляр существующей карты; это не ответ о генерации новых правил разработчиком.

Экраны: главное меню, настройки, магазин, коллекция/колоды, подготовка матча, матч. Безопасный обучающий бой. Подсветка успеха, объяснение ошибки, анимация урона, красная недопустимая цель, индикатор сохранения, диалог переподключения/выхода. Категории громкости, язык, будущая синхронизация. Сохранять после матча/пака/колоды/награды. Одна музыка достаточна для начала, три желательны; не превращать это в обязательные две.

Godot, типизированный GDScript, консольные тесты/экспорт, Android и Web, будущий 3D-слой без смены правил. Закрытые плагины запрещены. Команды/события, детерминизм, журнал, разделение правил и UI. Авторитет локальный/хост/сервер по режиму. Полный seed и скрытые колоды не выдаются оппоненту ради воспроизводимости.

## Текущий приоритет
Владелец изменил порядок на release-first: сначала воспроизводимая сборка, тест, APK, установка, затем магазин/крафт/новые механики. Исходная большая спецификация сохраняется в backlog, а не считается удалённой. Код Apache-2.0 по делегированной рекомендации; лицензии собственных ассетов отдельно.

## Верифицированное до новой реализации
Ветка bootstrap содержит техническое поле, UI, экспорт и Actions. Есть предыдущие успешные Android-сборки и prerelease. Это ещё не полноценный карточный бой, коллекция или система производства. Старый device script имел проблемы с PowerShell $PID и установкой без проверки SHA; старые CI ключи генерировались заново и ломали обновления. Исправления должны быть проверены, не объявлены заранее.

## Последовательность восстановления
1. Зафиксировать разрешения и решения.
2. Проверить reusable skill и запрет ложных PASS.
3. Реализовать малый детерминированный бой и headless-тесты.
4. Собрать APK с manifest и неизменной dev-подписью.
5. Установить на разрешённый телефон, сохранить локальную квитанцию.
6. Подключить bounded updater только для успешных dev prerelease, не выполнять чужие workflow на компьютере.
7. Получить ручную оценку; затем следующий небольшой выпуск.

Все фактические новые результаты — в SESSION_REPORT и CI; неизвестное остаётся неизвестным.
