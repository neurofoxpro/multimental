## Исправлен незакрытый дефект проверки исходников
На чистом снимке воспроизведено изменение main.gd: пробелы превращались в 297 табов после локального запуска редактора. Сам игровой код после обратного преобразования совпадал, но строгий gate справедливо отклонял изменившиеся исходники.

Добавлен изолированный self-contained Godot **только для локальной верификации**. Его настройки хранятся внутри снимка; личная конфигурация редактора и исходный executable не меняются. Исправлены также проверки свойств конфигурации, которые Godot переименовывает/не сохраняет как явные default-поля. Подробности и первоисточники: [SOURCE_STABILITY.md](SOURCE_STABILITY.md).

Production runner теперь сравнивает хеш исходников и до, и после команды. Даже exit code 0 не даст PASS, если команда изменила входные файлы. Проверка не игнорирует пробелы/табы и не скрывает изменение кода.

**Проверено на VENEL-SENDRIK:** 17 тестов Node; 3002 проверки ядра / 100 симуляций; headless UI. Верификация и последующий gate прошли **дважды** на одном снимке. Хеш личных настроек редактора до и после двух запусков совпал. [Обезличенное доказательство](evidence/isolated-verification.json), tested commit `d1345081...`. [PR8](https://github.com/neurofoxpro/multimental/pull/8) содержит исправление и результат CI; его статус проверяется перед merge, а не объявляется заранее.

## Что уже автоматизировано
Проверка разрешённого контекста → реальная верификация → APK на GitHub → manifest и checksum → dev prerelease → проверка происхождения/пакета/версии на станции → переподпись приватным dev-ключом → установка без очистки → проверка запуска → квитанция. Повторные запуски не переустанавливают ту же версию и не прерывают открытый матч.

25 этапов разработки оформлены в lifecycle. Реализованы скрипты формализуемых технических этапов, но ручная продуктовая приёмка и проектирование ещё не утверждённых механик не подменяются автоматикой. Магазин, крафт, сеть, рейтинг, итоговый баланс и финальный арт остаются в backlog.

## Что делать дальше
Настройку GitHub, runner и ADB повторять не нужно. Следующий шаг владельца — партия в **Multimental Dev**: выбрать карту, поставить на свободную клетку, выбрать своего юнита и атаковать соседнего врага, проверить понятность результата. Затем сообщить замечания по игровому процессу/читаемости. Следующий кодовый инкремент — эти исправления, затем каталог и конструктор колод через уже работающий скилл.

Для установки следующей проверенной версии нужно оставить компьютер включённым, войти в пользовательскую сессию, подключить разрешённый телефон и выйти из самой игры. Установщик проверит обновление в очередном цикле. Он не пишет новые механики и не выполняет загруженные скрипты.

Ни main, ни stable в этом продолжении не изменяются. Исторические квитанции всегда относятся к указанной версии; актуальный номер на телефоне проверяется заново.
