# MultiMental — экономия контекста и переход между чатами

Назначение: уменьшить объём повторяющихся данных в разговоре. Это **не** снимает платформенное ограничение максимальной длины чата.

## Начало нового чата

1. Прочитать `AGENTS.md` и `skills/game-production/SKILL.md` один раз за рабочую сессию. Пользоваться точечными ссылками на разделы, а не повторной загрузкой всех справочников.
2. В собственном разрешённом worktree выполнить `scripts\\chat.cmd focus`; при необходимости сначала прочитать `team status` и текущую координацию. Не претендовать на чужую задачу/ветку.
3. Проверить только **актуальную** задачу и изменившиеся решения из GitHub Issues; #29 — индекс, его старое описание не является свежим статусом.
4. Перед следующей операцией установить подтверждённые task ID, branch, HEAD, last verified stage и первый нерешённый blocker. Не додумывать их из старых чатов.

## Минимальный вывод в чат

- Успех: `TASK | stage | PASS | commit/PR | next`, обычно не более 5–10 строк.
- Ошибка: код выхода, короткая причина, только релевантный фрагмент stderr и путь к полному локальному логу/квитанции. Без секретов, токенов, серийных номеров и сырых телефонных логов.
- Полный stdout/stderr, большие JSON, патчи и отчёты сохраняются в предусмотренном evidence/log-хранилище, а не копируются целиком в чат. Если команда не имеет собственной записи лога, не скрывать её вывод без обеспечения сохранности диагностик.
- Не печатать полные файлы без необходимости. Выбирать нужные диапазоны, изменённые участки, `git diff --stat`, список затронутых файлов. Полный diff — только при необходимости проверки конкретного изменения.
- Для повторных запусков использовать имеющиеся resume/checkpoint; не начинать идентичные сборки и диагностику, если квитанция для того же входа уже действительна. При изменении source/config повторная проверка обязательна.
- После сбоя сначала читать checkpoint и точную ошибку. Не повторять побочные действия вслепую.
- Принятые решения, задачи и доказательства хранить в GitHub/репозитории, а не только в ответах ассистента.

## Конец завершённого инкремента

Записать состояние в **существующий** task Issue/#29 и штатные evidence/checkpoints:

```text
task: ID
branch / HEAD: verified identifiers
result: implemented | checked | shipped | blocked (separately)
evidence: links / exact receipt paths
blocker: first unmet stage or none
next: concrete command or task
```

Нельзя создавать конкурирующую «основную память». Не менять статус accepted, installed, CI green или released по тексту чата. Не выполнять checkpoint-запись, если её владелец или источник неизвестен.

## Объём рабочего пакета

Работать завершёнными инкрементами: конкретная задача → адресные файлы → проверка → evidence → продолжение. Предел не по произвольному числу операций; переключаться при росте объёма логов, повторных чтениях или переходе к независимой задаче. Не прерывать `ship`/установку/тест посередине ради экономии токенов.

## Возврат в новом чате

Достаточно фразы: «Продолжи MultiMental по AGENTS.md и текущим GitHub Issues. Сначала восстанови свою координацию и точный checkpoint, не перечитывай историю целиком». Не требовать ручного переноса всей переписки.
