# UX-11: подтверждение атаки после смены состояния

На базе 668cd6b6302a6b6e0fb55a5c61f157204556bc8e воспроизведена ошибка: предупреждение об ударе по союзникам сохранялось после двух переходов хода и могло выполнить старую команду на следующем своём ходу. Исходный тест дал шесть ожидаемых отказов в RU/EN.

Подтверждение теперь хранит копию команды и снимок публичного контекста: ход, события, сетевую ревизию/фазу, поле, монеты и размещение. При обновлении изменённого состояния диалог закрывается. Перед submit проверка повторяется, поэтому запоздалый callback не обходит защиту даже до следующего render. Отмена выбора также сбрасывает согласие.

Проверены сохранение согласия при неизменном refresh, обычный подтверждённый удар ровно один раз, смена хода/поля/монет/сетевой ревизии, ожидаемое подтверждение сети и reconnect. Interaction:126 PASS; directional UI:19 PASS; terrain:14510 PASS. Domain/replay/правила не менялись.

Сняты24 новых реальных source-render кадров. Вручную агентом осмотрены четыре кадра боя RU/EN в720x1280 и1280x720. Поле, характеристики, описание недоступных карт и footer видны; горизонтальная прокрутка руки намеренная. Это не пользовательская оценка. Полная UX-11 приёмка остаётся открытой: на альбомном кадре обрезано длинное русское имя юнита; галерея ещё не покрывает все состояния модального подтверждения.

Доказательства: docs/production/evidence/ux11-stale-confirmation-20261002.json. Выпуск и установка фиксируются отдельно по фактическому ship/phone result.
