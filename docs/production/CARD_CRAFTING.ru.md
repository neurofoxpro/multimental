# META-03: пыль, защищённый разбор и целевой крафт

Версионируемая alpha-конфигурация находится в `crafting_policy.gd`: создание40пыли, явный разбор10пыли, максимум2копии. Характеристики карты не меняются. Это тестовые значения, а не финальный баланс/реальные платежи.

Крафт: выбор конкретной карты → проверка недостающей копии и пыли → одна транзакция профиля. Разбор: выбор карты → проверка свободной копии → отдельный диалог подтверждения → одна транзакция. Для каждой карты защищается максимум необходимых копий по всем сохранённым колодам, включая неполные черновики. Карты не резервируются суммой между колодами, так как одновременно играется одна колода. Нужную копию, отрицательный баланс и переполнение API отклоняет до изменения состояния.

В существующей альфе30×2 уже выдано. Поэтому крафт не нужен до недостающей копии: интерфейс объясняет ограничение и не забирает старые карты ради демонстрации. Разбор свободной копии доброволен и не создаёт прибыльный цикл: восстановление стоит больше полученной пыли. Магазин даёт пыль за избыток; отдельная наградная экономика остаётся META04.

Коллекция, пыль и последняя квитанция сохраняются вместе через уже существующий ordered journal и два поколения. Потерянный ответ не порождает новую sequence: интерфейс удерживает исходную команду, блокирует смену карты и предлагает безопасный retry. Неизвестная версия crafting при открытии профиля даёт unsupported без перезаписи старшей сохранённой версии резервной копией.

Команды: `profile-test crafting`, `profile-test crafting-ui`, полный `check`, затем `device-suite --target phone --suite crafting` на точном установленном APK. Pure-тесты проверяют защиту колод,30типовкарт, отсутствие прибыли/усиления, конфликты ID, недостаток пыли, диск и потерю ответа. UI-тесты — подтверждение/отмена, меню, retry, restart, RU/EN и реальный viewport.

Аппаратная лаборатория использует случайный отдельный профиль. Она получает тестовую пыль через существующие команды магазина и ждёт5настоящих Android tap: открыть → разбор → подтвердить → создать → назад. Проверяются исходные колоды, две операции и остаток20пыли; личные a/b-файлы не меняются. Это не две физических Android-партии и не человеческая приёмка экономики.

Общий `ui-lab-spec.mjs` содержит стадии collection/shop/crafting; device runner сверяет все ожидаемые stages и каждую положительную проверку. PASS без полных checks больше не считается достаточным доказательством.
