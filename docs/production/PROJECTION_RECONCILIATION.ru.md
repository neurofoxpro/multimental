# Автоматическое согласование производственных документов

`workplan.json` — единственный редактируемый источник планирования. Обычный путь на разрешённой станции: `scripts/chat.cmd check`; он обновляет проекции и запускает аудит. Нельзя вручную подгонять requirements/backlog/roadmap к желаемому статусу.

Для изменения исходников через GitHub из чата проверен дополнительный CI-путь в текущей служебной ветке: owner push → генерация без write-токена → проверка схем/хешей/тестов → отдельный writer → обновление feature-ветки. Список допустимых файлов находится в `scripts/reconcile-projections.mjs` и не включает workflow, игру, ключи или другие ветки.

Точные ограничения: репозиторий neurofoxpro/multimental, branch feature/production-control-20260925, событие push, actor 4erk; максимум 2 MB содержимого; Git tree/commit/ref API; parent и HEAD сверяются до записи; force=false; итоговый ref читается повторно. Внешние PR никогда не получают writer. После неопределённого результата PATCH сначала читается ref, а не выполняется слепой повтор.

Путь реально проверен запуском 36171036763: 142 Node-теста прошли, восемь файлов согласованы коммитом 249bbb082616bf90c930b9244e8726bfa0101733. Это не означает merge в dev, APK-релиз или установку на телефон. Повторный прогон без изменений должен завершаться без нового коммита.

Bot-коммит через GITHUB_TOKEN не заменяет новый PR CI на его head. После readback агент делает следующий содержательный разрешённый коммит либо запускает доступную точную проверку и сверяет SHA. Не переносить результаты предыдущего head на новый. Квалификация кандидата и защищённые операции остаются в прежнем ops-процессе.

Расширение нормализатора на другие ветки или файлы — отдельное проверяемое изменение, а не глобальное расширение разрешений ради удобства. Для обычных последующих задач основной интерфейс остаётся `npm run game -- check` и `ship TASK-ID`.
