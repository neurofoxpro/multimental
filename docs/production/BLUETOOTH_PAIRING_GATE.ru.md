# Проверенная граница защищённого Bluetooth

24.09.2026 полный кандидат 0.3.0-alpha.67.1 прошёл 25 сценариев из 26. Не прошёл только новый защищённый Bluetooth-матч. Native connect вернул WSAEHOSTDOWN/10064. Эта ошибка сама по себе не доказывает точную причину.

Дополнительная независимая read-only проверка BluetoothGetDeviceInfo для конкретного телефона установила: адаптер присутствует, телефон известен Windows, но remembered=false и authenticated=false. Поэтому требование защищённого сопряжения не выполнено. Старый диагностический insecure RFCOMM проходил; это не основание убрать AUTHENTICATE/ENCRYPT в пользовательском режиме.

Теперь bluetooth-pairing показывает только флаги состояния без MAC/имени и не вызывает системное подтверждение. bluetooth-room проверяет этот prerequisite ДО закрытия игры/выключения Wi-Fi/попытки соединения. Он возвращает blocked/PAIRING_REQUIRED, а не passed, и не продолжает дорогой тест при известном незакрытом условии.

**Ручное действие:** в Windows на VENEL-SENDRIK открыть «Параметры → Bluetooth и устройства → Добавить устройство → Bluetooth», выбрать подключённый телефон; подтвердить совпадающий код на компьютере и на телефоне. Не подтверждать незнакомые устройства. Затем scripts/chat.cmd bluetooth-pairing должен показать authenticated=true. Подпись приложения, данные телефона и репозиторий менять не нужно.

После сопряжения нужно повторить защищённый тест и полную квалификацию текущего HEAD; наличие pairing не доказывает, что остальные стадии режима исправны. PR15 остаётся draft, до проверки он не объединяется и не выпускается как готовая версия.

Источники: Android Bluetooth connection guide; Microsoft BluetoothGetDeviceInfo и Bluetooth/socket options. Они подтверждают необходимость системной аутентификации, но фактические флаги получены с разрешённой станции, а не из документации.
