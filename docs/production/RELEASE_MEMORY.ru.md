# Автоматическая память выпущенных dev-сборок

После успешной публикации prerelease отдельный job `release-memory` выполняет `node tools/record-release.mjs`. Это не создание релиза, не merge и не установка на телефон: job фиксирует уже наблюдаемый результат в основной Issue #29.

Сверяются repository, package .dev, sourceBranch=dev, полный commit, workflowRun, версия, versionCode, имя APK и SHA-256 опубликованных APK/manifest. В комментарий попадают только версия, источник, идентификатор CI, ссылка и контрольные суммы. Сырые логи устройств и credentials туда не передаются.

Ключ комментария `gameprod:record:release-VERSION` делает повтор одинакового результата идемпотентным. После неизвестного результата записи сначала выполняется readback. Запись в Issues не должна выдавать старую квитанцию за новый артефакт.

Job имеет только contents:read и issues:write. Он выполняется после dev publication, не получает секреты для PR из форков и не использует pull_request_target. Его сбой не отменяет уже опубликованный APK: повторять следует только неуспешный job записи памяти, а не собирать новую версию ради комментария.

Локальный и GitHub-прогон тестов проверяют формат и отказы. Фактическое включение подтверждается первым успешным release-memory job и настоящим комментарием в #29. До этого нельзя объявлять автодокументацию релизов развёрнутой.
