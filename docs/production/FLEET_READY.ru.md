# Два разрешённых телефона: один проверенный APK, раздельные результаты

## Команды

~~~text
scripts\chat.cmd fleet known
scripts\chat.cmd fleet ready --target phone-A --commit ПОЛНАЯ_SHA
scripts\chat.cmd fleet ready --target phone-B --commit ПОЛНАЯ_SHA
scripts\chat.cmd fleet ready --target all --commit ПОЛНАЯ_SHA
~~~

phone-A - прежний основной Redmi из station.local.json. phone-B - ранее явно разрешённый HONOR BRC-NX1 из локального поручения device-requests/honor-install-20260927.local.json. Новый неизвестный телефон нельзя получить переименованием unbound-1. Прежний первичный serial и station.local.json не заменяются вторым.

known только наблюдает существующие соединения, не делает reconnect. Registered означает сохранённую известную физическую идентичность, не онлайн-состояние и не пройденный тест. Ready повторно находит ту же физическую идентичность через USB либо разрешённое mDNS TLS-подключение. Не используется сканирование подсети, принудительное pairing, tcpip5555 или перезапуск ADB-сервера.

## Общая подпись без копирования ключа

Сначала review ready --commit SHA должен создать опубликованный пакет ручной проверки. Fleet проверяет конкретный dev-релиз, опубликованный JSON-пакет, размер/хеш APK, соответствие игрового содержимого и прежний публичный сертификат основного устройства. На оба телефона устанавливаются одни и те же подписанные байты. Закрытый ключ не копируется в директорию второго телефона, не генерируется заново и не передаётся на устройство.

У уже установленного приложения проверяется фактический полный APK. Для другой старой версии считывается именно установленная APK и проверяется её сертификат. Чужая подпись, понижение версии или другие байты той же версии блокируют обновление без удаления приложения. Обновление выполняется только install-r. Потерянный ответ не означает повторную установку: сначала проверяется фактический результат; неизвестная незавершённая операция сохраняется и блокируется.

## Раздельные этапы и доказательства

Каждый телефон проходит установку либо сверку текущей версии, обычный запуск с READY, полный handoff-набор, проверку домашнего ярлыка и окончательную сверку APK/профиля. Две версии файлов профиля проверяются по SHA-256 до и после. Успешный пакет не утверждает ручную приёмку человека.

У каждого телефона свой каталог и install-operation/installed/target-квитанции. Primary остаётся на прежнем месте; Honor использует уже созданную отдельную директорию phones/honor-HASH. Во время теста второго телефона общий qualification-lock сохраняет первый updater без вмешательства. Дополнительные locks сериализуют запись исходников, установку и действия каждого устройства. Этот инкремент предпочитает корректную последовательность аппаратных действий параллельной гонке.

Основной launcher теперь допускает только одну дополнительную строго проверенную конфигурацию ранее разрешённого Honor. Эмуляторы по-прежнему принадлежат исходной станции; регистрация телефона не даёт права подставить произвольный executable, ключ, директорию или serial. Прежний основной маршрут не зависит от повреждённой вторичной записи.

Результат all при одном доступном телефоне - partially_ready и код завершения2. Второе устройство явно unavailable. Один телефон через USB+Wi-Fi не становится двумя. Для общего PASS нужны две разные физические идентичности и одинаковые байты/сертификат. Даже это не доказывает общую партию или Bluetooth: radioTestPassed остаётся false, сетевое испытание - отдельный маршрут с захватом обоих ресурсов.

## Защита Wi-Fi-отладки

Выявлен опасный прежний маршрут: legacy Bluetooth-тест отключал Wi-Fi, хотя теперь ADB тоже работает через Wi-Fi. Это могло разорвать единственный канал управления до восстановления сети. Перед любым отключением Wi-Fi и изменением Bluetooth-разрешений такой тест теперь требует USB-контроль. При Wi-Fi возвращается BLUETOOTH_NO_WIFI_TEST_REQUIRES_USB_CONTROL, связь и настройки не трогаются.

Настоящий Bluetooth с сохранённым Wi-Fi-контролем можно проверять отдельным NET-04 сценарием, доказывая транспорт полезных данных. Этот legacy-тест продолжает проверять именно сценарий без Wi-Fi и не выдаёт другой сценарий за него. TCP-forward через Wi-Fi ADB теперь помечается как ADB_WIFI_TUNNEL_NOT_DIRECT_LAN, а туннель эмулятора - как не физический USB. Прямой LAN остаётся отдельным тестом.

## Текущее ограничение Honor

Ранее APK на Honor установилась, но требуемый READY не был получен из logcat. Наличие процесса или изображения меню не подменяет эту проверку. Сейчас Honor не объявлен в mDNS; код не меняет системную политику логирования, блокировку экрана или защиту устройства, чтобы добиться PASS. При возвращении устройства новый маршрут продолжит с фактической версии и старой подписи; пропущенная аппаратная приёмка остаётся открытой.

## Первичные источники, проверено28.09.2026

https://developer.android.com/tools/adb - USB/Wi-Fi, конкретная цель -s, mDNS и предварительное разрешение отладки. Более новые рекомендации ADB Wi-Fi2.0 относятся к соответствующим версиям Android; текущие телефоны Android15 не обновляются этой задачей.
https://developer.android.com/studio/publish/app-signing - идентичность подписи и безопасное обновление приложения.
https://developer.android.com/tools/logcat - свойства наблюдения Android-журналов. Пустой журнал не доказывает готовность приложения.

Остановленный ранее общий пакет с заменой signingDirectory не используется. Реализован узкий новый маршрут установки уже опубликованной manual APK на два устройства, отдельно и явно разрешённые владельцем. Это не изменение принятых игровых правил, интерфейса или дизайн-лаборатории.
