# Ядро сверки рабочего плана с GitHub Issues

Основная память — определения и обсуждения Issues. Файловый workplan должен быть воспроизводимым снимком, а не конкурирующим источником статуса. Например, META-05 уже закрыта в Issue30, хотя прежний файловый снимок ещё содержит planned.

`skills/game-production/scripts/plan-snapshot.mjs` содержит чистую функцию `proposedSnapshot(seed, snapshot)`. Она не выполняет команды, не обращается к сети, не пишет файлы и не разрешает публикацию. Возвращает предложенный план и список изменений с номерами Issues и хешами их описаний.

Принимается только полный live-снимок того же репозитория. Проверяются timestamp, уникальность задач/номеров, наличие всех прежних задач, хеши первичных записей, граф зависимостей и доказательства verified. Новая неизвестная задача и удаление обязательного Play-объёма требуют отдельного решения; молчаливое изменение области не выполняется.

Неизменный снимок не обновляет дату. Повторное применение даёт пустой diff. Результат копируется и не меняет переданный объект. Закрытая Issue сама по себе не считается доказательством прохождения тестов; используются типизированные определения с evidence.

## Состояние интеграции

В этой итерации реализовано и протестировано только чистое ядро. Подключение команды `github snapshot-plan` к flow было остановлено проверкой инструмента; команда НЕ доступна и файловый workplan НЕ синхронизирован этим модулем. Не удалять защиту и не повторять заблокированную запись альтернативным путём.

План следующего разрешённого изменения: получить live snapshot → показать diff → проверить наличие readset/evidence → применить через штатный apply с текущим HEAD и хешем → render → verify → сохранить квитанцию. Ошибка между шагами должна оставлять явное состояние и безопасную команду восстановления. Никакого разрешения main/stable/Play через данные Issue.

Тесты pure-модуля входят в общий `node tools/source-tests.mjs`: неизменность, идемпотентность, aliasing, полнота, дубликаты, timestamp, неверные хеши, ложный verified, path traversal, зависимости и защита объёма. Эти unit-тесты не доказывают интеграцию рабочего pipeline.
