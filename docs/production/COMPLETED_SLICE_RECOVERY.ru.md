# Освобождение доказанно завершённого среза

```text
scripts\chat.cmd collab recover-completed QA-02
scripts\chat.cmd collab recover-completed QA-02 --apply
```

Первая команда только наблюдает. Вторая разрешена из чистого, проверенного среза с кодом, уже входящим в dev. Оператор имеет собственный действующий claim области automation/coordination/workspaces; он не выдаёт себя за прежнего владельца.

Недостаточно просроченного heartbeat. Проверяются зарегистрированный sibling worktree, точные origin/HEAD/ветка/binding, отсутствие правок и незавершённых PR, один canonical merged dev PR на этом HEAD, оба merge parent, ancestry в наблюдённом dev, завершённые Actions и отсутствие действующих операционных блокировок. Неизвестность останавливает операцию. Открытый PR119 не подходит; завершённый PR116 является реальным положительным контрольным случаем.

На применение резервируются target ops, dev integration и station qualification через существующие exclusive leases. Чужие lock не удаляются и процессы не завершаются. Затем все факты читаются повторно. Полный fingerprint claim включает heartbeat: продление до записи делает пакет недействительным. GitHub createCommitOnBranch применяет expectedHeadOid; потерянный ответ проверяется по уникальному событию, повторный release не отправляется.

Изменяется только удаление завершённого claim из coordination-state и добавление квитанции события. Исходники, незакоммиченные файлы, прежний binding, телефонные настройки и ключи не меняются. Старый binding сохраняется как история, но уже не проходит текущую проверку владения. После освобождения новая работа получает новый обычный collab start; задача QA02 не закрывается самим освобождением.

Результаты записываются в задачу, Issue29 и задачу оператора. Повтор команды после потерянного ответа использует сохранённый operation ID и readback. Журналы хранятся в .gameprod/evidence/completed-recovery; старые операции не заменяются другой задачей. Проверка совместного протокола не является защитой от администратора, который пишет в обход всех инструментов.

## Контрольные проверки
28 чистых/интеграционных тестов: успешное освобождение только цели, сохранение другого claim, идемпотентность, изменения proof/heartbeat/source, открытые PR, незавершённые Actions, занятые lease, неизвестный оператор, lost CAS reply и сбой записи памяти. Реальный read-only probe признал QA02 eligible и отказал UX07 с RECOVERY_EXACT_MERGED_PR_REQUIRED. Применение считается выполненным только по последующей реальной квитанции, не по этим предварительным строкам.

## Урок UTF-8 при передаче в Node
Windows PowerShell может передать кириллицу в pipeline как вопросительные знаки даже при UTF-8 Console. Для `... | node` задаётся также `$OutputEncoding=[Console]::OutputEncoding`. Русское определение AUTO11 было повреждено при создании предложения; единственная собственная Issue122 восстановлена с проверкой предыдущего body hash и повторным чтением, без изменения смысла критериев. Определения задач из чужих источников не исправляются догадками.
