# Короткий рабочий цикл

В своём срезе: `scripts/chat.cmd focus` → `apply BUNDLE.json` → `ship`. Отдельный check полезен в процессе, но ship сам выполняет полную проверку. Для нового среза один раз: `collab start TASK UNIQUE_ALIAS`; работать только в возвращённом каталоге.

## Focus
Живые критерии/зависимости, собственные HEAD/ветка/draft, claims, состояние ship и хеши необходимых входов. В консоли три последних комментария задачи и два нерелизных обновления памяти с отметкой усечения. Полные данные — .gameprod/evidence/focus.local.json; task ID — полный вид. Это индекс для адресного чтения, не обещание учесть нечитанную историю. Первые/изменившиеся решения читаются полностью, старые всеархивные простыни не повторяются.

## Ship
Снимок Issues → существующие check/publish/github settle/wait-dev → наблюдение релиза → идемпотентная запись в задачу/Issue29. Старые dispatch-маршруты не включаются. Проверки source-seal, точных head/base, machine COMMENT review и ограничений dev сохраняются. Изменение source/claim на границе этапа останавливает цепочку.

Журнал .gameprod/evidence/ship.json связывает задачу, owner/token, ветку, fingerprint, PR и commit. Потерянный ответ публикации/merge проверяется чтением. Повтор завершённого ship не публикует/сливает снова. Docs-only PR не требует выдуманного APK. Для кода проверяются успешный dev build, один prerelease на точном merge, загруженные APK/manifest и их GitHub SHA-256 метаданные. Это наблюдение публикации, не проверка установленного файла.

Вывод ограничен стадиями/результатом, подробные stdout/stderr сохраняются локально. Таймауты конечны. Не запускать второго писателя при живом/неизвестном lock. Полное восстановление всех осиротевших процессов — отдельная AUTO-07; эта команда не удаляет их блокировки наугад.

## Устройства
Телефон не условие ship. Затем device-status, при необходимости delivery, device-suite --target phone --suite rewards (или нужный набор). Уже установленный updater-ом APK не выдаётся за установку своего чтения. Второй телефон/подпись/радиотест имеют отдельную задачу и leases.

## Приёмка
`accept META-04 docs/production/evidence/rewards-completed-20260926.json` работает только из чистого среза с завершённым ship. Proof уже должен быть в Git. Проверяются repository/task/точные критерии, source-bound verify, реальный implementation PR, его parents, CI/source-seal и отсутствие чужого claim. Продуктовые/субъективные/внешние/release gates не закрываются этим кодом.

Меняются только status/evidence управляемого определения и Issue state; несвязанная авторская часть сохраняется. До PATCH перечитывается body, после — readback, включая потерянный ответ. У REST Issue API не заявляется server-side CAS: короткое окно после последнего чтения не скрыто словом «атомарно». Смысл критериев проверяет агент и прикладывает доказательство; один валидный JSON не является независимой приёмкой.

Историческая verified не квалифицирует новый RC. Следующий ship синхронизирует plan/roadmap, live Issue доступна сразу. Публикация, установка и ручная оценка — отдельные результаты.

## Windows composition lesson
Исходные пакеты собирать из обычных строк: File.ReadAllText или Node JSON.stringify. PowerShell Get-Content может вернуть строки с PSProvider/PSDrive-свойствами; глубокий ConvertTo-Json такого объекта способен зависнуть до записи пакета. Исходники всё равно меняются только через apply с exact HEAD/hash. Факт создания JSON не является фактом применения.

## Следующий инкремент и исправление CI

Журналы раздельны по веткам в .gameprod/evidence/ships; ship.json — последняя сводка. После закрытого PR используется collab branch suffix и новый ship. Для исправленного открытого PR: ship --revise. Команда требует прежний точный remote head, тот же claim, сохранённую Git-родословную и новые исходники, архивирует предыдущую квитанцию и повторяет полную проверку. Уже влитый PR, неопределённая публикация и неизменённый исходник отклоняются. Форматирование доходит до устойчивого результата за ограниченное число проходов; цикл/нестабильность — ошибка.

## Проверенные эксплуатационные исправления

Временные ошибки соединения и усечённый JSON GET повторяются в общем ограниченном бюджете до трёх попыток. Неопределённые записи POST/PATCH/PUT не повторяются: нужна проверка результата по идентичности операции. Окончательное падение CI возвращает blocked сразу, без восьмиминутного ожидания. Диагностический вывод сохраняет первый значимый сбой, а не только успешные тесты в конце журнала.

Активный ship блокирует посторонние исходниковые записи в этом worktree, включая прямой apply. Его дочерним стадиям передаётся привязка к root/PID/token живого родителя. Это кооперативный протокол процессов, не защита от администратора. При accept сравнивается Git clean-хеш с HEAD blob, публичный SHA-256 считается от канонических байтов Git. Windows CRLF не выдаётся за изменённое доказательство; настоящий изменённый файл или неверный blob отклоняются.
