# Продолжение из нескольких чатов без конкурирующих записей

Единственная точка проекта: neurofoxpro/multimental, память Issue29, skill `skills/game-production/SKILL.md`. Сначала читать live состояние, а не повторять старый архив. Для личного выполнения разрешена только VENEL-SENDRIK.

## Новый чат

1. Прочитать AGENTS/skill/Issue29. `npm run game -- resume` показывает актуальные задачи и зависимости.
2. `npm run game -- collab start TASK-ID UNIQUE-CHAT-ALIAS` атомарно получает claim и создаёт отдельный worktree. Перейти в каталог, выданный командой. Не редактировать общий repo или чужое дерево.
3. `collab check-owner`, затем `task TASK-ID`. Если ресурс занят, выбрать независимую задачу или ждать; истечение TTL не разрешает захватить его молча.
4. Изменения только через apply с точным HEAD/хешами; повторные операции — через skill. Продлевать claim командой `collab renew`, а не вручную править binding.
5. Когда другой чат продвинул dev, `collab refresh` допускает только безопасный fast-forward с непересекающимися черновиками. Для настоящего текстового конфликта нужен отдельный проверяемый merge, не reset/rebase.
6. `check` → `publish MESSAGE TITLE` → `github settle PR EXACT_HEAD` → `wait-dev MERGE`. Установка телефона отдельна; отсутствующий телефон не блокирует dev.
7. Результат/ошибки/следующую команду записать в Issue задачи и29. Обновить версионный снимок через `github snapshot-plan` и штатный проверяемый PR. Завершив или передав задачу, `collab release` освобождает только собственный claim, не удаляя исходники.

## Что проверено в этой волне

Экономика, UX и диагностика получили разные claims и деревья. Параллельно работали облачные Linux/Windows проверки, независимая разработка и изолированные тесты одного телефона. Срез UX пережил продвижение магазина, сохранив10черновых файлов; crafting пережил продвижениеUI, сохранив7. Все вливания прошли local settle с exact head/base. Это проверенная командная координация, не утверждение о бесконечно работающих LLM-агентах после завершения чата.

На текущей личной станции фактически готов один ADB-телефон. `fleet usb` даёт дополнительную read-only диагностику Windows, но не заменяет RSA-согласие и не делает вид, что два USB-интерфейса — два телефона. Serial/ключи остаются локальными.
