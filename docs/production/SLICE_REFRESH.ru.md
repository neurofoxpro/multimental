# Обновление параллельного среза без потери черновиков

Команда: `npm run game -- collab refresh`. Она работает только в текущем связанном feature/fix/docs/test worktree с живым GitHub claim. Не меняет чужой checkout или служебную coordination-state ветку.

Если текущий HEAD — предок точного наблюдаемого dev, выполняется исключительно `git merge --ff-only --no-autostash SHA`. Перед этим сравниваются имена входящих путей с локальными staged/unstaged/untracked изменениями, включая регистр и конфликт файла/каталога. Пересечение останавливает обновление. Дивергенция требует отдельного ревью слияния: reset/rebase не выполняются.

Перед операцией сохраняются план, branch, claim и хеши всех локальных изменённых файлов. Владение повторно проверяется, после Git сверяются точный HEAD, неизменность branch и байтов черновиков. Запись под per-slice ops.lock. Неопределённый результат не приводит к автоматическому rollback или удалению данных: журнал остаётся для разбора.

В этой итерации команда реально подтянула срез UX с d4797322eb196981cb6bf99fb61fd4d41f94d02e до099d0f5b61546b97407090c7e6a6e7793f050b75 после независимого магазина PR111, сохранив10 черновых файлов. Это не имитация двух агентов: одновременно выполнялись независимые Actions, телефонный тест и работа в другом дереве, а запускал их один чат.

После обновления проверки выполняются заново. Серверный dev может позднее продвинуться ещё раз: кандидат всё равно обязан пройти CI/source-seal на фактической комбинации base/head. Команда не обещает автоматически решать текстовые конфликты между двумя изменениями одного файла.
