# Восстановление очереди установки после завершения владельца

Команды: `npm run game -- device-recover plan` и `npm run game -- device-recover apply`. После восстановления отдельно `delivery`, затем `device-status` и нужные наборы проверок. Разрешённая станция и конфигурация берутся из существующего проекта, не из произвольного пути пользователя. Команда не доступна в CI.

Проверяются только install.lock, device-test.lock, qualification.lock и update.lock. Файлы должны быть обычными небольшими JSON-файлами с корректным PID и временем. Самого возраста недостаточно: обязательна ошибка ESRCH от проверки процесса сигналом 0. Живой PID, переиспользованный PID или неизвестное состояние сохраняют блокировку.

До изменения архивируются точные байты. Все свободные имена блокировок временно заняты текущим процессом; существующие ещё раз сверяются по хешу и файловой идентичности. Затем только подтверждённо оставшиеся без владельца файлы переносятся в отдельный каталог lock-recovery с квитанцией, а не уничтожаются. Последующие собственные блокировки снимаются проверкой владельца. Никакой процесс не завершается.

Гарантия относится к сотрудничающим проектным процессам: это не файловая compare-and-swap транзакция против сторонней программы, произвольно переименовывающей файлы. Неизвестный результат или изменившийся файл прекращает цепочку, промежуточный архив сохраняется. Повтор начинает с нового наблюдения; нельзя слепо возвращать старые файлы поверх нового владельца.

Ключи, APK, личный профиль и установленная версия этой командой не меняются. Квитанция recovered означает только восстановление координации. Установка, запуск и аппаратные проверки подтверждаются независимо.
