# Домашний ярлык и завершение установки

## Команды

`launcher verify --target phone` проверяет настоящий текущий домашний экран и запуск через существующий значок. `launcher ensure --target phone` дополнительно использует штатный запрос закрепления, когда значок не найден. Для отдельной виртуальной среды — `--target emulator-A` или `emulator-B`.

Обе операции проверяют фактическую APK/версию/подпись, профиль до/после, известную физическую идентичность или имя назначенной AVD. Неизвестный второй телефон не подставляется. Старый ярлык сначала ищется на ограниченном числе страниц с проверкой foreground именно текущего default launcher. Хеши страниц записываются, названия остальных приложений и их координаты не публикуются. Если значок найден и запускает Multimental Dev, второй не создаётся.

## Нативное закрепление

В dev-APK добавлен изолированный LauncherSupport autoload. Без небольшого точного запроса из `user://automation-launcher-request.json` он не вызывает Android API и ничего не меняет. Запрос содержит только режим, схему, nonce и точную установленную версию. Неизвестный, слишком большой или чужой запрос сохраняется, а не выполняется.

Сначала проверяются собственный package, поддержка requestPinShortcut и уже закреплённый стабильный ID `multimental-manual-v1`. Новый ShortcutInfo использует штатный стартовый intent и иконку приложения. Запрос вызывается в Android UI thread через встроенные Godot JavaClassWrapper/AndroidRuntime, Java-исключения проверяются после каждого вызова. Никакой установки внешних APK, root, редактирования базы launcher или deprecated broadcast нет.

Если launcher показывает штатный диалог, автоматизация нажимает только однозначную видимую кнопку добавления в том же launcher, при совпадающих package, nonce, версии и названии Multimental Dev. Это выполнение прямого поручения владельца добавить значок, а не обход Android. Чужие кнопки, неоднозначный диалог, PIN/пароль/биометрия не нажимаются и не вводятся. Отказ или отсутствие подтверждения остаются явным блоком.

Даже статус getPinnedShortcuts не принимается за готовый домашний значок: нужен повторный реальный поиск и запуск приложения именно через него. Неизвестная предыдущая операция сначала сверяется с файлом результата и исходным nonce; подтверждение не повторяется вслепую. Сохраняются установленная подпись, профиль и все посторонние домашние элементы.

## Встраивание в lab

После установки и программных проверок `lab deliver` / `lab test` выполняют ensure автоматически. Если значка нет и launcher не подтвердил закрепление, весь цикл не объявляется полностью готовым к ручной игре. Повтор `lab resume` повторно наблюдает домашний значок, но не повторяет уже подтверждённую установку и неизменный тестовый набор. Home-screen проверка может запускать уже установленное приложение — это целевой проверяемый эффект, не лишний reinstall.

Standalone scheduled updater по-прежнему устанавливает APK; итоговая проверка пригодности к ручной игре принадлежит lab-циклу. Наличие регулярного Android-ярлыка обычно сохраняется при обновлении, но в отчёте оно подтверждается наблюдением, а не предположением. Все дальнейшие этапы подписи/второго устройства/QA-03 имеют собственные критерии.

## Первичные источники

- https://developer.android.com/develop/ui/compose/system/shortcuts/creating-shortcuts — поддержка launcher, requestPinShortcut, стабильные ID и подтверждение.
- https://docs.godotengine.org/en/4.7/tutorials/platform/android/javaclasswrapper_and_androidruntimeplugin.html — встроенный AndroidRuntime, UI thread, конструкторы и вложенные Java-классы.
- https://docs.godotengine.org/en/stable/classes/class_javaclasswrapper.html — обязательная проверка исключений после Java-вызовов.

Headless-тесты валидируют запрос, но не означают реально созданный ярлык. Реальный платформенный результат фиксируется отдельным тестом на текущей APK. Ключи подписи и личный профиль не публикуются.
