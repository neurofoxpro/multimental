# Ручная проверка релиза без подключения телефона

## Одна команда

~~~text
scripts\chat.cmd review ready
scripts\chat.cmd review ready --commit ПОЛНАЯ_SHA
scripts\chat.cmd review resume
~~~

Команда выбирает реально опубликованный dev-предрелиз, фиксирует его commit и исходный APK, прогоняет на выделенном Android-эмуляторе полный handoff-набор и возвращает конкретные ссылки на APK, релиз, исходники, инструкцию и предзаполненный отзыв. Телефон может находиться вне домашней сети, без USB и без ADB. review status показывает сохранённый пакет; это не новая проверка удалённых файлов.

Не используется /releases/latest: он не обозначает нужный предрелиз. Ссылка закреплена за конкретной версией и файлом, каждый опубликованный asset проверяется по размеру и SHA-256. Неудачная отправка сначала сверяется с GitHub; повтор не заменяет существующий файл и не отправляет неизвестный результат заново. Immutable release не размораживается автоматически.

## Зачем отдельный manual APK

Основной файл CI подписан временным debug-ключом runner. Уже установленная на основном телефоне игра использует постоянный закрытый dev-ключ станции. Поэтому прямая замена установленной игры исходным CI APK может дать конфликт подписи.

Review создаёт дополнительный файл manual с прежним постоянным сертификатом, не меняет пакет приложения и не генерирует новый ключ. Все полезные ZIP-записи исходного, проверенного на эмуляторе и скачиваемого manual APK сравниваются по содержимому; исключается только оболочка подписи. Сертификат и хеш APK публичны; private key, пароль, личные данные и ADB-идентификаторы остаются на станции. Подпись эмулятора не выдаётся за подпись телефона.

При отсутствии исходного постоянного ключа публикация обновления останавливается. Уже существующий APK с другими байтами не перезаписывается. На неизвестном устройстве нельзя обещать совместимость с любой ранее установленной подписью: при конфликте не удалять приложение и данные, а вернуть конкретную ошибку.

## Раздельные критерии готовности

Для выдачи пакета обязателен полный компьютерный сценарий: close → launch → JNI → tutorial → UI → inspector → collection → restore, неизменная APK и точные квитанции каждого шага. У lab появился явно обозначенный режим --readiness software: только полный handoff и только выделенная виртуальная среда. Он не запрашивает домашний ярлык в эмуляторе и не стирает прежний неподтверждённый запрос.

Обычный lab test по-прежнему выполняет свой launcher-этап. Software-ready не равен готовому ярлыку на физическом телефоне, Bluetooth-проверке или человеческой приёмке. В пакете эти пункты остаются pending/not_checked. Таким образом недоступный телефон и отдельный launcher-gate не блокируют выдачу реально проверенной игры разработчику.

## Что получает проверяющий

На странице того же dev-релиза появляются подписанная APK и MANUAL_REVIEW-...md/json: версия, commit, исходный и итоговый хеши, сертификат, состав компьютерной проверки и сценарий на5–10минут. Есть ссылка на создание Issue с уже заполненной версией, SHA и полями воспроизведения. Отзыв не отправляется и задача не закрывается автоматически.

С телефона достаточно открыть ссылку через доступный интернет, скачать APK и подтвердить штатную установку. Не требуется быть в одной сети с компьютером. При полном отсутствии интернета APK надо скачать заранее либо перенести доступным способом; ссылка не является доставкой на полностью отключённое устройство. Нельзя обходить системную защиту или удалять сохранения ради установки.

## Источники и принятый вариант

- Android signing: https://developer.android.com/studio/publish/app-signing — обновления и подпись, private key остаётся закрытым, сертификат можно распространять.
- GitHub release assets: https://docs.github.com/en/rest/releases/assets — browser_download_url, состояние/размер/digest, upload и readback.
- GitHub release links: https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases — ссылка на конкретный тег/asset.

Проверены27.09.2026. Выбран GitHub Releases, уже используемый проектом: без нового сервиса, регистрации тестировщиков, Google Play или раскрытия ключа. Web-preview, QR и магазинная внутренняя группа могут добавляться отдельными задачами; здесь они не объявляются реализованными.

## Совместимость с существующим ship

В релизе остаётся ровно один основной CI APK. Дополнительные manual-варианты допускаются только с точным именем этой версии/commit и сертификатным суффиксом; неизвестный второй APK, дубликат или неподтверждённый asset отвергаются. Повторный ship продолжает указывать исходный CI SHA, а не подпись телефона. Отдельная регрессия проверяет совместимость публикации и приёмки.
