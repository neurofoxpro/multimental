# Multimental: отчёт о выполненной работе — 24.09.2026

## Результат
Первая играбельная Android-альфа **реально установлена** на телефон, подключённый к **VENEL-SENDRIK**. Затем установленная задача Windows **сама обновила** её с `0.1.0-alpha.20.1` до `0.1.0-alpha.23.1`. Запуск подтверждён процессом, версией пакета и отметкой `MULTIMENTAL_READY`. Настройка языка пережила обновление. Данные приложения не удалялись.

Единственный репозиторий — `neurofoxpro/multimental`. Другие компьютеры и репозитории в этой работе не использовались. `main` не изменена, stable-релиз не выпускался.

- [Восстановленный контекст чата](CHAT_RECOVERY.ru.md) с сохранением отложенных механик и исходной цели, без превращения предложений в утверждённые правила.
- Проверки репозитория/хоста, команд с таймаутами, исходников и отчётов. Нельзя получить PASS без запуска; изменённые исходники, лог или APK делают квитанцию недействительной.
- Headless-проверки, сборка Android, автоматический prerelease, установка и проверка запуска, планировщик последующих обновлений.

Скилл использовался для текущей проверки и сборки, а не просто записан как инструкция. Универсальная часть принимает явный профиль и команды движка. Android/Godot-адаптеры находятся в scripts/tools данного проекта. Это автоматизация формализуемой работы, **не обещание самостоятельного придумывания всех будущих игровых механик**.

## Выполненные проверки
**15 тестов Node:** запрет другого хоста/репозитория, обхода путей, неоднозначного телефона, неверного манифеста/хеша, ложных/устаревших отчётов; правильная обработка генерируемых UID; канонические адреса загрузки; ожидание холодного запуска; отказ при отсутствии ready и при runtime-ошибке.

**3002 проверки ядра, 100 симуляций:** допустимость команд, неизменность после отклонения, очередность, размещение, бой и одновременное уничтожение, победа за пятую клетку, истощение руки/колоды, два пропуска, воспроизведение по журналу.

**Headless UI:** меню, переключение языка, запуск, девять клеток, выбор карты и цели, появление юнита, возврат в меню.

**Физический телефон:** установка, повторная установка/обновление без очистки, сохранение языка, запуск, просмотр меню и поля, реакция на недопустимую цель, завершение по таймауту. Полная ручная партия и субъективная оценка удобства ещё **не приняты пользователем**.

## Исправленные проблемы
Исторические ветки dev и bootstrap расходились. Изменения сравнены и объединены с сохранением обеих историй; force-push не применялся.

Godot создавал `.gd.uid`, из-за чего первоначально срабатывала проверка изменения исходников. Генерируемые sidecar-файлы перечислены отдельно; изменение `.gd` продолжает блокировать PASS. Добавлен регрессионный тест.

На первом физическом запуске проверка через 2,5 секунды была преждевременной. Реальный ready пришёл позже. Установщик теперь ожидает его ограниченное время и не засчитывает наличие процесса как полную готовность.

Старый PowerShell-установщик с конфликтом `$PID`, установкой без проверки манифеста и возможным удалением данных заменён проверяемым Node-адаптером.

## Подпись: важная граница
Скачанный CI APK и установленный APK **не побитово одинаковы**. CI использует временную debug-подпись; разрешённая станция проверяет исходный APK, затем переподписывает постоянным **локальным приватным** dev-ключом. В квитанции сохранены оба SHA-256 и отпечаток сертификата. Один сертификат использовался для 20.1 и 23.1. Приватный ключ не опубликован.

Этот механизм предназначен для тестового пакета `pro.neurofox.multimental.dev`. Промышленная подпись/Google Play — отдельный будущий этап; текущий CI APK не выдаётся за готовый канал долгосрочных публичных обновлений. Подробности: [SIGNING.md](SIGNING.md).

## Как работают последующие обновления
После принятого изменения в dev GitHub Actions проверяет код, собирает APK, сохраняет manifest/checksum и публикует prerelease. На VENEL-SENDRIK установлена задача **Multimental-Dev-APK-Updater**, интервал **5 минут**, права **Limited**, интерактивная сессия пользователя.

Задача проверяет именно neurofoxpro/multimental, успешный push-workflow dev, commit тега, package/version/SHA. Загружает APK и данные, **не выполняет новые скрипты из репозитория**. Устанавливает обновление на выбранный авторизованный телефон без удаления данных. Если игра на переднем плане, установка откладывается. Компьютер должен работать, пользователь быть вошедшим, телефон — подключён и разрешён для ADB, сеть — доступна для GitHub.

Настройка, отключение и ручной запуск: [DEVICE.md](DEVICE.md), [scripts/register-updater.ps1](../../scripts/register-updater.ps1). Исполняется локальная проверенная копия `agent-c13e98788902`; обновление самого установщика требует отдельной проверки и развёртывания.

## Рабочая папка станции
`%USERPROFILE%\MultimentalWork`: portable tools, независимые снимки исходников, проверенный агент, приватная конфигурация станции, локальные журналы и результаты установок. Полный телефонный serial и ключи не копируются в GitHub. Повторный bootstrap не удаляет существующий проект и не создаёт другой репозиторий.

## Что ещё не сделано
Коллекция/конструктор, магазин/паки/крафт, дополнительные ресурсы, новые свойства, финальный арт/звук, LAN/Bluetooth, Web-релиз, аккаунты и рейтинг остаются в backlog. Баланс текущих карточных параметров временный. Полный комплект правовых уведомлений, аудит pinned Actions/зависимостей и серверные branch protections требуют отдельного шага перед внешним стабильным выпуском.

После успешного обновления канал Remote Desktop VENEL-SENDRIK стал недоступен. Это **не доказательство выключения компьютера или остановки планировщика**. Результат последней повторной проверки той же версии не был прочитан; его нужно проверить при восстановлении связи. На другой компьютер не переключались. Также зафиксировано изменение пробелов на табы в локальной копии main.gd после теста: guard корректно пометил отчёт stale, CI APK собран из неизменного GitHub commit. Причину локального изменения нужно выяснить, не отключая guard.

## Следующее действие
Пользователь открывает **Multimental Dev** и проводит партию против ИИ. Первый цикл обратной связи — читаемость, выбор карты/цели, атаки и темп. После этого исправления и новые механики проходят скилл и тот же конвейер до телефона. Уже настроенную доставку не строим заново.
