# Единое управление производством Multimental

Один публичный вход: `npm run game -- КОМАНДА`. На разрешённой Windows-станции то же делает `scripts/chat.cmd КОМАНДА`. Старые ops-команды сохранены для совместимости, а не являются новой параллельной системой. Рабочий репозиторий только neurofoxpro/multimental, станция только VENEL-SENDRIK.

## Минимальная последовательность

```text
npm run game -- next
npm run game -- task META-05
npm run game -- start META-05
npm run game -- check
npm run game -- ship META-05
```

`next` выбирает готовые по зависимостям задачи. `task ID` выдаёт readset, критерии, ограничения и готовые команды. `start ID` создаёт feature/ветку по ID, без придумывания имени. Код реализации всё ещё пишет агент; эта команда не изображает создание игры автоматически.

`check` синхронизирует производные документы, проверяет реестр, затем вызывает существующий аудит: форматирование, тесты и ревью. `ship ID` использует существующий проверенный `ops cycle`: проверки → PR → CI → кандидат → требуемая квалификация → dev → релиз → сохранная доставка → отчёт. Он не сливает main и не публикует Google Play. Для кода сохраняются все прежние обязательные hardware gates. Offline-станция не даёт права их обходить.

После прерывания: `npm run game -- resume`; затем указанная в результате точная стадия, для уже объединённого цикла — `npm run game -- resume-cycle`. Не запускать второй cycle на уже опубликованный результат.

## Идеи и эксперименты

`npm run game -- idea IDEA-001 "Описание идеи"` записывает предложение без исполнения его текста и без автоматического принятия. Каждая идея должна получить задачу или явное решение с источником. Отложенная идея не исчезает из закрытия проекта.

`npm run game -- experiment BALANCE-01` запускает существующую ограниченную симуляцию: профиль current, count 40, seed 9001, уникальное имя результата. Это конкретный baseline-эксперимент, не универсальная реализация произвольной идеи и не доказательство человеческого баланса. Новые виды экспериментов добавляются тестируемыми адаптерами, а не shell-командами из текста карты.

## Источник истины

`.gameprod/workplan.json` — задачи, зависимости, критерии, источники, readset и исторические доказательства. Из него командой `render` получаются requirements.json, backlog.json, roadmap.json и docs/ROADMAP.ru.md. `render --check` запрещает дрейф производных файлов. Старые реестры сохранены в docs/production/archive; state.json остаётся историей наблюдений, а не процентом текущей готовности.

`verified` означает историческое доказательство по ссылке, а не новое разрешение выпуска. Допуск нового кандидата по-прежнему сверяет SHA, fingerprint, журналы и артефакты в существующем ops. `assessReceipt` — дополнительный тестируемый контракт для будущего release adapter, не замена текущей квалификации.

## Закрытие и Play

`npm run game -- closeout` выводит незакрытые задачи и идеи. Он намеренно не способен разрешить production одной правкой статусов: свежий RC, одобрение, фактическая публикация и магазинная установка требуют отдельных проверок.

`npm run game -- play-check` — только предварительный контроль конфигурации и локальной инспекции AAB. До появления Publisher API adapter/защищённого workflow он ничего не загружает. Подробный путь и ручные ограничения: PLAY_RELEASE.ru.md.

## Контракт каждого нового адаптера

До добавления команды нужны: входная схема; разрешённые репозиторий/хост/пакет/трек; конечный timeout; argv без shell; один владелец операции; идемпотентность либо readback после неопределённого результата; source-bound receipt; тесты отказов; точная команда resume; минимальный пакет следующему агенту.

Нельзя закрыть отсутствие коллекции, магазина, аккаунтов или upload-кода статусом «человек проверит». Действия человека: смысл отложенной механики, субъективная игра, физические разрешения, реальная регистрация/верификация и одобрение выпуска. Действия Google: eligibility и review.
