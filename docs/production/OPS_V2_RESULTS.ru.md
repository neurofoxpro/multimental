## Что теперь автоматизировано
Рабочий вход: **[skills/game-production/SKILL.md](../../skills/game-production/SKILL.md)** и **[scripts/chat.ps1](../../scripts/chat.ps1)**. Ниже команды для агента и повторного использования; пользователю не требуется вручную собирать APK или настраивать GitHub заново.

```powershell
.\scripts\chat.ps1 resume
.\scripts\chat.ps1 begin feature/next-change
# Здесь выполняется необходимое изменение кода/данных игры.
.\scripts\chat.ps1 cycle "feat: description" "Название изменения"
# При изменении сетевого/аппаратного взаимодействия:
.\scripts\chat.ps1 cycle "feat: transport change" "Название изменения" --physical
```

Цикл сам проверяет допустимый компьютер/origin/аккаунт, выполняет тесты, коммитит, публикует PR, ждёт проверки именно нужного HEAD, получает проверенный APK, испытывает его в выделенных AVD, допускает merge только в dev, дожидается релиза, устанавливает его и сохраняет отчёт. Для целевой диагностики: prepare, candidate, qualify, device-test, probe-bluetooth. Для продолжения после уже выполненного merge: resume-cycle. Для записи отчёта: report --write.

Сценарии не претендуют на самостоятельное утверждение ещё не согласованных механик. Агент занимается содержательным изменением игры; повторяемая доставка и контроль выполняются инструментами.

## Быстродействие и устойчивость
**Git worktree вместо новых архивов исходников.** Portable Git и gh используют уже выданный доступ venelsendrik. Браузер Chrome, повторная авторизация, новый токен и права ADMIN для выполненной работы не потребовались.

**Меньше лишних сборок.** Один PR-контур вместо дублирования каждого push feature-ветки. Документация/roadmap проходят metadata/security-проверки без нового APK. Godot и нужные Android/Web-шаблоны кэшируются; Actions зафиксированы commit SHA. Universal APK содержит arm64 для телефона и x86_64 для эмуляторов.

**Один изменяющий процесс.** Операционная аренда запрещает конкурирующие циклы и редактирование через штатный apply во время испытаний. Исходный fingerprint сравнивается до и после команды; изменившийся тестируемый код не получает PASS. Это контроль инструментов и результатов, а не заявление о системной блокировке всех сторонних редакторов.

**Установщик и испытания не мешают друг другу.** Новые фоновые обновления откладываются при qualification/device lock. Уже начавшаяся установка завершается в ограниченное время перед тестом; её не убивают и не удаляют живой lock. Повтор той же установки идемпотентен.

**Точный релиз, а не exit 0.** Один раз список релизов ещё показывал старую публикацию после успешного CI. Теперь ограниченное ожидание нужного merge commit входит в cycle/resume-cycle. Нулевой код без фактически установленного нужного APK не считается успехом. История исправления — [RELEASE_VISIBILITY.ru.md](RELEASE_VISIBILITY.ru.md).

## Исправления, найденные испытаниями
На проводе JSON-числа нормализуются к валидированным целым; дробные seq/координаты и лишние поля отклоняются. В JNI явный трёхаргументный write устраняет потерю ответа; этот вызов проверяется на эмуляторе до радиотеста. Системная подсказка Android о fullscreen больше не перекрывает клетку в тестовом AVD: baseline и точная UIAutomator-проверка обрабатывают только известную подсказку на выделенном эмуляторе. Подробности — [TRANSPORT_FINDINGS.ru.md](TRANSPORT_FINDINGS.ru.md).

## Автообновление и данные
На VENEL-SENDRIK зарегистрирована задача **Multimental-Dev-APK-Updater**, интервал **5 минут**, ограниченные права. По последнему поручению включено автоматическое закрытие тестового приложения перед обновлением. Используется install -r, не удаление данных. Чистая установка разрешена только двум именованным AVD; реальный телефон таким режимом защищён от очистки.

Ключ подписи остаётся приватным на станции; после проверки CI APK переподписывается постоянным локальным dev-ключом. В отчёте отдельно указаны исходный SHA-256 и SHA-256 установленного файла. Это документированный тестовый способ обновления, не окончательная production-подпись для Google Play. Сертификат телефона сохраняется между версиями. В публичных отчётах нет serial, MAC/IP, nonce, ключей и полных телефонных логов.

Для последующих установок достаточно включённого VENEL-SENDRIK с вошедшим пользователем, подключённого и авторизованного телефона и доступа к GitHub. Сам установщик не исполняет новые скрипты из GitHub: обновление его проверенной копии — отдельная операция deploy-agent.

## Что осталось
**Сетевое пользовательское лобби/PvP не объявляется готовым.** Сейчас проверен транспорт и диагностическая сессия авторитетного ядра. Далее нужны создание/вход в комнату, два человеческих игрока, права ролей, discovery/сопряжение, полноценный reconnect и интерфейс ошибок. Bluetooth-лаборатория — ограниченный тестовый insecure RFCOMM с nonce; безопасное production-сопряжение — следующий этап, не скрытый выполненный пункт.

Коллекция/сборка колод, магазин/пак из 5 карт/крафт, дополнительные ресурсы, центральная система свойств, Web, аккаунты/рейтинг и финальная аудиовизуальная часть — в **[roadmap по версиям](../ROADMAP.ru.md)**. Принятые правила и отложенные решения находятся в **[.gameprod/decisions.json](../../.gameprod/decisions.json)**; очередь — **[backlog](../../.gameprod/backlog.json)**.

Следующий содержательный инкремент — **0.2.0, пользовательский LAN-матч**, а не повторная настройка CI/ADB/репозитория. В его проверки добавляются разрывы/возвраты, потеря/дублирование/перестановка сообщений, право каждого игрока и отсутствие утечки скрытой руки. Человеческая оценка первой партии остаётся независимой задачей и не блокирует формализуемую инженерную работу.
