# История изменений Multimental

Этот файл генерируется из changes/fragments. Записи описывают изменения для человека, а не сырой Git log.
Базовые версии обозначают серии разработки, не факт выпуска stable. Точный номер alpha, commit и проверки опубликованы в GitHub Release.

Порядок разделов основан на Keep a Changelog; совместимость — по согласованному SemVer.

## 0.12.0 — текущая серия разработки

### Добавлено

- Завершённый чужой срез освобождается проверяемой командой по точным PR/source/claim под блокировками; открытая работа и один лишь просроченный heartbeat не дают права на захват.
- Награды завершённых партий, два добровольных офлайн-задания и уровни без усиления карт; сохранение без двойного начисления и без сброса открытой коллекции.

### Изменено

- Короткий строгий скилл: focus для актуальной задачи, возобновляемый ship для проверенного dev-выпуска и accept для приёмки по версионным доказательствам.

### Исправлено

- Временные GET-обрывы восстанавливаются без повторения записей; активный выпуск блокирует чужую правку исходников, а квитанции проверяются по каноническим байтам Git вместо ошибочного сравнения CRLF.

## 0.11.0 — предыдущая серия alpha

### Добавлено

- В коллекции и создании карт появилась отдельная кнопка подробностей: крупный текст характеристик, зоны удара, дружественного огня и ответа противника. Общий диалог прокручивается, закрывается кнопкой или Escape и возвращает фокус; чтение не меняет колоду и валюты.
- Проверка подробностей карты на Android повторно использует общий протокол касаний и изолированный профиль. Шесть реальных нажатий проверяют открытие и закрытие из коллекции и крафта, сохранность черновика и отсутствие списаний. Сигнальная проверка лаборатории и физический прогон учитываются отдельно.

## 0.10.1 — предыдущая серия alpha

### Добавлено

- Добавлена диагностика USB-интерфейсов Windows вместе с ADB, без смены драйверов, разрешений или режима подключения. Интерфейсы одного контейнера не выдаются за несколько телефонов; идентификаторы скрыты.

### Исправлено

- Аппаратные проверки теперь вычисляют касание в viewport самого элемента, включая встроенное окно подтверждения, а не в корне. Подтверждение разбора локализовано и получило крупные кнопки; отмена и защита нужных копий сохранены.

## 0.10.0 — предыдущая серия alpha

### Добавлено

- Добавлено целевое создание карты за пыль и подтверждаемый разбор только свободной копии. Копии, нужные любым сохранённым колодам и черновикам, защищены. Карта, пыль и квитанция сохраняются одной идемпотентной операцией, характеристики карт не улучшаются.

## 0.9.1 — предыдущая серия alpha

### Исправлено

- Устранено обрезание нижних кнопок главного меню на коротких и альбомных экранах: ограниченная прокрутка сохраняет размер текста и целей. Добавлены предсказуемый начальный фокус, автоматическая прокрутка к нему и контрастная рамка для клавиатуры.

## 0.9.0 — предыдущая серия alpha

### Добавлено

- Добавлен локальный магазин паков по пять карт: единая транзакция оплаты и выдачи, восстановление последнего пака, повтор без двойного списания и конвертация лишних копий в пыль. Тестовые 500 монет выдаются один раз при явном входе; реальных платежей нет.
- Параллельный срез можно одной командой безопасно подтянуть fast-forward к текущему dev с сохранением непересекающихся черновиков по точным хешам. Дивергенция и конфликт путей требуют отдельного решения, никакого reset/stash/force.
- Добавлен воспроизводимый аудит реальной геометрии интерфейса в 24 комбинациях экрана и языка с проверкой фактического viewport, изоляцией профиля и отдельными результатами для прокручиваемых элементов. Рекомендации редизайна опираются на первичные источники и измерения, не подменяют человеческую приёмку.

## 0.8.0 — предыдущая серия alpha

### Добавлено

- Собственные выбранные колоды передаются в LAN/Bluetooth до начала матча, проверяются хостом и не меняются при переподключении. Скрытые составы не добавлены в публичные проекции; обеим сторонам требуется совместимый протокол комнат v3.
- Добавлена координация параллельных чатов через атомарный GitHub-журнал владения, изолированные рабочие срезы и проверку текущего владельца перед записью. Метки, приоритеты и нативные зависимости Issues синхронизируются командой и dev-workflow; создание среза не означает запуск автономного агента.
- Отдельная Android-лаборатория проверяет редактор, сохранение, выбор и запуск своей колоды восемью настоящими нажатиями в изолированном профиле. Цели нажатия привязаны к этапу и одноразовому запросу; снимки экрана больше не перезаписываются между запусками.
- Добавлена read-only проверка подключённых физических Android без публикации serial и без подмены первого телефона вторым. Неоднозначность, отсутствие авторизации и незавершённая регистрация второго устройства явно отделены от успешной установки.

### Исправлено

- При первом запуске отдельного рабочего среза подготавливается локальный кэш классов Godot. Изолированные профильные тесты также импортируют проект перед запуском и не зависят от ранее открытого редактора.
- Регрессия плана проверяет сохранение требований, источников и инженерной ответственности, а не замораживает завершённую коллекцию навечно в planned. Синхронизация подтверждённого прогресса больше не ломает CI.

## 0.7.1 — предыдущая серия alpha

### Исправлено

- Восстановление очереди после завершившегося владельца блокировки выполняется отдельной командой: PID проверяется без завершения процессов, точные файлы архивируются, живые и неизвестные владельцы не затрагиваются. Установка и данные телефона проверяются отдельно.
- Обучение запускается с собственной стартовой колодой даже при неполном или невыбранном личном составе. Оно не инициализирует коллекцию и не меняет сохранённый выбор; обычный AI-матч по-прежнему требует законную выбранную колоду.

## 0.7.0 — предыдущая серия alpha

### Добавлено

- Доступен экран коллекции и редактор именованных колод: поиск RU/EN, стихии, состав, сохранение черновика, выбор и бой с ИИ собственной колодой. Действуют правила 15 карт/2 копии, подтверждение удаления и потери несохранённых изменений. Первый вход выдаёт бесплатный тестовый набор один раз; сетевые партии пока используют прежнюю стартовую колоду.

## 0.6.0 — предыдущая серия alpha

### Добавлено

- После успешных PR-проверок CI отдельно подтверждает точные head/base и merge-checkout. Старый успешный запуск на другом основании не является допуском новой комбинации. Это read-only этап для дальнейшего автоматического dev-вливания, а не разрешение production.
- Добавлено проверяемое ядро коллекции: стабильные ID карт, сохранение именованных колод, проверка принадлежащих копий и запуск матчей с заданными составами с точным replay. В этом инкременте редактор ещё не включён, обычное меню сохраняет прежнюю стартовую колоду; Android-лаборатория проверяет новые записи без изменения личного профиля.
- Одной командой актуальные определения GitHub Issues переносятся в проверяемый снимок плана и производные документы. Сверяются полный набор задач, зависимости, доказательства и точные исходные байты; повтор не переписывает неизменный план и восстанавливает прерванную генерацию.
- Локальная команда завершения PR объединяет ожидание точных CI, машинное ревью, повторную проверку refs и безопасное вливание в dev с чтением результата. Отсутствие телефона не блокирует merge; публикация и доставка проверяются отдельно.
- Локальный профиль сохраняет язык, локальную статистику боёв и последний replay боя с ИИ. Два проверяемых поколения позволяют восстановиться после повреждённой записи; компактный журнал не начисляет повторные результаты. Добавлены отдельные проверки диска, интерфейса и Android без изменения личного профиля.

## 0.5.1 — предыдущая серия alpha

### Добавлено

- Очистка уже влитых рабочих веток вынесена в отдельную команду: точные SHA, проверка dev-родословной, защита активных рабочих деревьев, открытых PR и незавершённых Actions. Удаление выполняется атомарно через beforeOid с force=false и последующим чтением результата.
- После публикации dev-сборки отдельный job сверяет источник и контрольные суммы опубликованных APK/manifest и идемпотентно записывает результат в основную Issue памяти. Публикация, установка и ручная приёмка остаются разными состояниями.
- Команды продолжения и задач читают основную память GitHub Issues; добавлены параллельные проверки исходников на Windows/Linux и модель профиля с идемпотентными транзакциями. Дисковое сохранение профиля и полный автовлив остаются отдельными незавершёнными стадиями.
- Единый вход человека и агента связывает идеи, задачи, проверки и существующий dev-цикл; полный граф до Google Play сохраняет прежние решения, отделяет исторические доказательства от допуска кандидата и явно показывает отсутствующую реализацию.

### Изменено

- После сравнительных симуляций усилены обычные стрелки (атака 1→2) и копейщики (здоровье 2→3), снижено здоровье обычных фланкеров (3→2). Стоимость карт и правила поля сохранены. Добавлены воспроизводимый запуск симуляций и отчёт; сетевой идентификатор баланса обновлён.

### Исправлено

- Автопроверка PvP учитывает союзников во всей зоне атаки, а не только выбранную цель; ожидание матча считается после подключения. Диагностический Bluetooth-клиент ограничивает частоту ping. Эмуляторы используют GPU разрешённой станции вместо проблемного программного OpenGL backend.
- Проверки телефона привязаны к уникальному запуску, точному установленному APK и неизменным исходникам. Старые квитанции и ошибочные параметры не могут дать успех; обновление блокируется на весь набор. Добавлены независимые smoke, USB и Bluetooth-наборы, локальные архивы и 58 регрессионных тестов.

## 0.4.0 — предыдущая серия alpha

### Добавлено

- **Несовместимое изменение.** Добавлены пять стихий, направления и поворот карт до размещения, пять тактических типажей, добровольная атака новым юнитом или прежним за одну монету, дружественный огонь с подтверждением, стартовая монета второму игроку и визуализация урона. Новые правила несовместимы с прежними сетевыми партиями.

## 0.3.0 — предыдущая серия alpha

### Добавлено

- Проверка Windows↔Android различает наличие адаптера и подтверждённое сопряжение выбранного телефона. Диагностика не публикует MAC и не вызывает автоматическое подтверждение пользовательского pairing.
- Добавлен Android-режим Bluetooth с выбором сопряжённого устройства, приватным приглашением и тем же авторитетным ядром комнаты. Используется защищённый RFCOMM без обхода системного сопряжения; аппаратная приёмка фиксируется отдельно.

### Изменено

- Квалификация сама выбирает аппаратные проверки при изменении транспорта, экспортных разрешений или нативного Bluetooth-кода. Обычные UI/документационные правки не требуют радиоустройств; новый защищённый Bluetooth-сценарий нельзя пропустить при интеграции.
- Длительная квалификация отдаёт прогресс по каждому завершённому сценарию сразу, сохраняя отдельные квитанции и конечный timeout. Агенту больше не нужно многократно читать огромный общий лог в ожидании завершения.

## 0.2.1 — предыдущая серия alpha

### Добавлено

- Аудиоматериалы воспроизводимо генерируются скриптом из оригинального алгоритма. CI проверяет формат PCM, длительность, пиковую амплитуду и совпадение файлов, без ручной подготовки ассетов.
- В обязательную Android-квалификацию добавлены реальные касания ползунка громкости и обучающей карты/клетки, проверка сохранения настроек и восстановления их исходного значения после испытания.
- Добавлены безопасная обучающая партия, пошаговые подсказки, оригинальная фоновая композиция и звук успешного действия. Общая громкость, музыка и эффекты настраиваются отдельно и сохраняются.

### Исправлено

- Артефакты CI скачиваются с докачкой по Range и сохранённой неизменной идентичностью. Таймаут больше не обнуляет полученные байты; готовый ZIP принимается только по SHA-256 GitHub, а повторное извлечение проверяет уже существующие файлы.

## 0.2.0 — предыдущая серия alpha

### Добавлено

- Все требования чата сведены в машиночитаемый реестр; gate готовности к бете отличает невыполненную реализацию от действительно ручной оценки и запрещает выдавать одно за другое.
- Добавлены создание LAN-комнаты и подключение второго игрока по приватному приглашению, авторитетные ходы двух игроков, защищённый TLS-канал и автоматическое переподключение.
- Команда handoff готовит перенос в новый чат: разрешённая станция, точный Git/PR, установленная версия, непройденный этап, решения и ручные пункты. Короткий Windows-вход chat.cmd не меняет системную execution policy.
- Добавлен проверяемый реестр исследований: вопрос, рекомендация, первоисточник, связанные тесты и ограничения. Рабочий инструмент проверяет реестр и сохраняет хеши исследованных источников.

### Исправлено

- Идентификация выделенных эмуляторов учитывает двойной CR в выводе ADB на Windows, сохраняя строгую проверку имени и запрет очистки настоящего телефона.
- Для временного fetch failed и HTTP 502/503/504 при чтении метаданных добавлен ограниченный повтор. Ошибки доступа, rate limit, неверный JSON и превышение размера не обходятся.
- При создании комнаты Wi-Fi и проводная локальная сеть предпочитаются VPN и мобильному интерфейсу; подходящий адрес можно явно выбрать в лобби.
- Сериализация сертификата комнаты изолирована от ошибки NUL в Godot; проверка сертификата и имени узла остаётся включённой, приватный ключ не записывается на диск.
- Офлайн- и сетевой интерфейсы используют одну проекцию состояния без чужой руки; причины завершения переведены на русский и английский, а завершение по таймеру сохраняется.
- Чтение GitHub повторяется только при временных сетевых сбоях; результат неоднозначного merge проверяется без повторной записи. Параллельная установка корректно откладывается, не удаляя живой lock.
- После Bluetooth-проверки восстановление Wi-Fi считается выполненным только после получения адреса. Следующий LAN-тест ждёт ассоциации с конечным таймаутом вместо ложного сбоя сразу после включения радио.
- Общий JSON-писатель повторяет временный Windows sharing violation; при длительной блокировке rename сохраняет предыдущую и новую версии, проверяет запись и явно отмечает неатомарный fallback. Ошибки прав, диска и конкурирующего изменения не обходятся.

## Проверки и ограничения

Автоматические проверки и установка привязаны к конкретному APK; их результаты не выводятся из списка изменений.
Ручная приёмка: docs/MANUAL_TESTS.ru.md. Полный план: docs/ROADMAP.ru.md.
